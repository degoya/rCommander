# scripts/

Every build, check, package and repository chore of rCommander is a script here; nothing is
retyped by hand. The heavy ones take the build lock themselves (`scripts/lib/lock.sh`,
`/tmp/rc-build.lock`) - never wrap them in `flock`. The public repository on GitHub leaves out
the maintainer's own workflow scripts that `public-exclude.txt` names (job files, worktrees, the
local CI, measurements, the live servers); their rows below describe the development repository.

| Script | What it does | Lock |
| --- | --- | --- |
| `check.sh --preflight` | Compiles nothing: `cargo fmt --check`, `bash -n` and Python syntax, shellcheck (and its version against `lib/tool-versions.sh`), the script tests (`scripts/tests/*.sh`), gitleaks, `git diff --check`, `archive-jobs.sh --check`, the 500-line rule, `cargo deny --offline check`, the migration pins (`sha384sum -c` of `crates/rc-db/migrations.sha384`, and every `.sql` has a pin), `set-version.sh --check`, `licenses.sh --offline --check`, `mcp-coverage.sh --check`, `keyboard-reference.sh --check`, `settings-reference.sh --check`, `check-sdk-templates.sh`, `wit-reference.sh --check`, `plugin-manifest-defaults.sh --check`. A missing shellcheck, gitleaks or cargo-deny, or another shellcheck version, is a `skip` here and a failure under `--full` | no |
| `check.sh --rust` | `cargo clippy --workspace --all-targets -D warnings`, `cargo nextest run --workspace --no-fail-fast` (in nextest's profile `NEXTEST_PROFILE`), and `wasm32-clippy`: `cargo clippy --target wasm32-unknown-unknown -D warnings` over the plugins and `rc-plugin-types`, `rc-plugin-text`, `rc-plugin-api` (lib only, their guest code; `target/lanes/wasm32`) | yes |
| `check.sh --windows` | `cargo xwin clippy --target x86_64-pc-windows-msvc --workspace --all-targets -D warnings`, then `windows-lib`: the same without `--all-targets`, the libraries with the features they ship with (no dev-dependency features); in `target/lanes/windows` | yes |
| `check.sh --full` (default) | All three. Green on a clean tree, it stamps HEAD in the checkout's git directory (`git rev-parse --git-path rc-check-full`) for `worktree.sh finish` | yes |
| `nightly.sh` | `check.sh --full` with `NEXTEST_PROFILE=ci` (JUnit, one retry, flaky tests named), the exit as the log's last line `REAL EXIT: <n>`; logs and JUnit in `RC_NIGHTLY_LOGS` (default `~/.local/state/rcommander/nightly`), the newest `RC_NIGHTLY_KEEP` (14) kept. | `install-hooks.sh [--pre-push] [--timer [--at HH:MM]] [--remove]` | Installs or removes the pre-push hook (`hooks/pre-push.sh`: `check.sh --preflight`, a copy in `git rev-parse --git-path hooks`; a foreign hook is left alone) and the nightly timer (`systemd/rcommander-nightly.{service,timer}` into `~/.config/systemd/user/`, 03:00 unless `--at`, `systemctl --user enable --now`); both without an option. | `worktree.sh new <name>` | Branch `feature/<name>` from `development`, worktree at `../rcommander-wt/<name>` | no |
| `worktree.sh finish <name>` | Clean tree required; merges `--no-ff` into `development`, removes worktree and branch. Warns before the merge when the worktree has no green `check.sh --full` stamp on the branch's tip (`RC_FINISH_REQUIRE_GREEN=1` refuses instead) | no |
| `worktree.sh list` | The worktrees and their branches | no |
| `set-version.sh [X.Y.Z] [--check]` | Prints, sets or checks the one workspace version (`Cargo.toml`, `Cargo.lock`, the SDK templates' `min_app_version` and the `RCOMMANDER_VERSION` pin of `sdk/ci/*.yml`); a new version cuts `CHANGELOG.md`'s `[Unreleased]` into `## [X.Y.Z] - <date>` (`lib/changelog.sh`, test `tests/changelog.sh`) | no |

`check.sh` runs every stage even after a failure, prints a summary and ends with `REAL EXIT: <n>`;
`==> all requested checks passed` appears only when every stage was green. Each run logs into its
own directory, `$RC_CHECK_LOGS/<time>-<pid>/` (default `RC_CHECK_LOGS` is
`/tmp/claude-<uid>/check-<checkout>`): one log per stage, `summary` and `failures`.
